## 1. Обзор продукта

### 1.1 Что такое MentorHub

MentorHub — кросс-платформенный маркетплейс менторинга, объединяющий менторов и менти в единой экосистеме. Платформа предоставляет полный цикл менторских взаимодействий: от поиска и подбора ментора до проведения сессий, оплаты, отслеживания прогресса и оценки результатов.

### 1.2 Видение продукта

Создать глобальную платформу, которая делает качественное менторство доступным каждому — от начинающего специалиста до корпоративной команды. MentorHub стремится стать стандартом индустрии менторинга, заменив разрозненные инструменты (календари, мессенджеры, платёжные системы) единым решением.

### 1.3 Текущая версия

Продукт находится на этапе **v2.0** с реализованными модулями:

| Версия | Фокус | Статус |
|--------|-------|--------|
| v1.0 (MVP) | Аутентификация, бронирование, уведомления | Завершён |
| v2.0 | Платежи, отзывы, мессенджер, геймификация, маркетплейс | Завершён |

## 2. Проблема и рыночный контекст

### 2.1 Проблемы, которые решает MentorHub

**Для менти (учеников):**
- Сложно найти подходящего ментора с проверенной экспертизой
- Нет единого места для бронирования, оплаты и коммуникации
- Отсутствие объективных метрик прогресса и ROI от менторинга
- Непрозрачное ценообразование и риски при оплате

**Для менторов:**
- Административная нагрузка: расписание, напоминания, платежи
- Отсутствие инструментов для масштабирования практики
- Нет платформы для построения публичной репутации
- Сложность управления множеством менти одновременно

**Для организаций (B2B):**
- Нет инструментов для запуска внутренних программ менторинга
- Невозможно измерить ROI от менторских программ
- Отсутствие контроля качества менторинга

### 2.2 Рыночный контекст

Глобальный рынок менторинга и коучинга оценивается в $20+ млрд и растёт на 15-20% ежегодно. Ключевые тренды:

- Рост удалённой работы увеличивает спрос на онлайн-менторинг
- Корпорации инвестируют в развитие сотрудников через менторские программы
- Рост экономики создателей (creator economy) стимулирует индивидуальных экспертов монетизировать знания
- AI-технологии открывают возможности для умного подбора и аналитики

### 2.3 Конкурентная среда

| Конкурент | Сильные стороны | Слабые стороны | Наш ответ |
|-----------|----------------|----------------|-----------|
| MentorCruise | Большая база менторов | Нет видео, ограниченная аналитика | Полный цикл: видео + аналитика + геймификация |
| Clarity.fm | Экспертные созвоны | Нет долгосрочных отношений | Система целей и прогресса |
| ADPList | Бесплатные менторы в дизайне | Узкая ниша, нет монетизации | Мультидоменный маркетплейс с платежами |
| Calendly + Stripe | Гибкость настройки | Не специализирован под менторинг | Единое решение «под ключ» |

### 2.4 Конкурентные преимущества MentorHub

1. **All-in-one решение** — бронирование, платежи, мессенджер, аналитика в одном месте
2. **Геймификация** — уникальная система мотивации с очками, достижениями и лидербордами
3. **Структурированный прогресс** — цели, вехи, метрики результата
4. **Мультиканальные уведомления** — Email, Telegram, Push, SMS
5. **B2B + B2C** — единая платформа для индивидуальных менторов и корпоративных программ

## 4. Ценностное предложение

### 4.1 Value Proposition Canvas

**Для менти:**
> "Найди проверенного ментора, забронируй сессию в два клика и отслеживай свой прогресс — всё в одном месте."

**Для менторов:**
> "Сфокусируйся на менторинге, а не на администрировании. MentorHub автоматизирует расписание, платежи и коммуникацию."

**Для организаций:**
> "Запусти программу менторинга для команды с измеримыми результатами и прозрачной аналитикой."

### 4.2 Ключевые дифференциаторы

1. **Единая экосистема** вместо 5-7 отдельных инструментов
2. **Измеримые результаты** через систему целей, вех и аналитики
3. **Мотивация через геймификацию** — уникальная механика вовлечения
4. **Прозрачность и доверие** — верифицированные отзывы, рейтинги, статистика
5. **Глобальная доступность** — мультивалютность (135+ валют), мультиязычность

## 5. Функциональные требования

### 5.1 Модуль аутентификации и авторизации (v1.0)

**FR-AUTH-001: Регистрация пользователя**
- Регистрация через email + пароль
- Валидация email-формата и силы пароля
- Назначение роли (MENTOR, MENTEE) при регистрации
- Верификация email (отправка ссылки подтверждения)

**FR-AUTH-002: Аутентификация**
- Вход по email + пароль
- Выдача JWT access token (TTL: 15 минут)
- Выдача refresh token (TTL: 7 дней)
- Механизм обновления access token через refresh token
- Logout с инвалидацией токенов

**FR-AUTH-003: Авторизация**
- Role-based access control (RBAC): MENTOR, MENTEE, ADMIN
- Guard-based защита эндпоинтов
- Разграничение доступа к ресурсам по владельцу

**Acceptance Criteria:**
- [ ] Пользователь может зарегистрироваться с уникальным email
- [ ] Пароль хешируется через bcrypt (10+ rounds)
- [ ] Access token истекает через 15 минут
- [ ] Refresh token позволяет получить новый access token
- [ ] ADMIN имеет доступ ко всем ресурсам
- [ ] MENTOR/MENTEE имеют доступ только к своим ресурсам

### 5.2 Модуль управления пользователями (v1.0)

**FR-USER-001: Профиль пользователя**
- Просмотр и редактирование профиля
- Поля: имя, фамилия, аватар, био, headline, timezone, язык
- Социальные ссылки: LinkedIn, Twitter, Telegram, сайт
- Видео-интро (URL)

**FR-USER-002: Профиль ментора**
- Расширенные поля: опыт (лет), почасовая ставка, время ответа
- Публичность профиля (isPublic)
- Премиум-статус (isPremium)
- Статистика: рейтинг, кол-во отзывов, кол-во сессий, выручка
- Категории экспертизы

**FR-USER-003: Управление аккаунтом**
- Деактивация аккаунта
- Смена пароля
- Управление настройками уведомлений

**Acceptance Criteria:**
- [ ] Профиль ментора отображает все метрики
- [ ] Смена timezone корректно влияет на отображение слотов
- [ ] Деактивированный аккаунт не может авторизоваться

---

### 5.3 Модуль типов встреч (v1.0)

**FR-MT-001: Создание типа встречи**
- Ментор создаёт типы встреч с параметрами:
  - Название и описание
  - Длительность (15/30/45/60/90/120 минут)
  - Цена (или бесплатно)
  - Валюта
  - Цвет для календаря
  - Лимит бронирований в день
  - Буферное время между встречами
  - Настраиваемые поля формы бронирования (JSON)
  - Флаги: активно/неактивно, запись сессии

**FR-MT-002: Управление типами встреч**
- CRUD-операции для менторов
- Активация/деактивация без удаления
- Просмотр типов встреч ментора (публичный)

**Acceptance Criteria:**
- [ ] Ментор может создать до 10 типов встреч
- [ ] Буферное время учитывается при расчёте доступных слотов
- [ ] Неактивные типы не отображаются для менти

---

### 5.4 Модуль расписания и доступности (v1.0)

**FR-AVAIL-001: Настройка рекурентного расписания**
- Ментор задаёт еженедельные слоты доступности
- Параметры: день недели, время начала, время окончания
- Поддержка timezone-aware расписания
- Множественные слоты в один день

**FR-AVAIL-002: Исключения из расписания**
- Разовые изменения: отпуск, выходной, доп. слот
- Тип: UNAVAILABLE (блокировка) или AVAILABLE (доп. слот)
- Диапазон дат и времени

**FR-AVAIL-003: Расчёт доступных слотов**
- Алгоритм расчёта свободных слотов для конкретного ментора и типа встречи
- Учёт: рекурентное расписание + исключения + существующие бронирования + буфер
- Учёт timezone менти при отображении

**Acceptance Criteria:**
- [ ] Слоты корректно генерируются с учётом часового пояса менти
- [ ] Занятые слоты исключаются из доступных
- [ ] Буферное время между встречами соблюдается
- [ ] Исключения перекрывают базовое расписание

---

### 5.5 Модуль бронирования (v1.0)

**FR-BOOK-001: Создание бронирования**
- Менти выбирает ментора, тип встречи и свободный слот
- Указывает обязательные поля из формы бронирования
- Бронирование создаётся в статусе PENDING
- Отправляются уведомления ментору (Email + Telegram)

**FR-BOOK-002: Управление бронированием**
- Жизненный цикл: PENDING → CONFIRMED → COMPLETED
- Отмена бронирования (менти или ментор) → CANCELLED
- Перенос (reschedule) — выбор нового слота
- Пометка как NO_SHOW
- Валидация конфликтов при создании/переносе

**FR-BOOK-003: Уведомления по бронированиям**
- Автоматическое напоминание за 24 часа
- Автоматическое напоминание за 1 час
- Уведомление о создании, подтверждении, отмене, переносе
- Каналы: Email, Telegram

**Acceptance Criteria:**
- [ ] Невозможно забронировать занятый слот (конфликт)
- [ ] Ментор получает уведомление о новом бронировании
- [ ] Напоминания за 24 ч и 1 ч до сессии отправляются автоматически
- [ ] При отмене все стороны получают уведомление
- [ ] Перенос освобождает старый слот и занимает новый

### 5.6 Модуль уведомлений (v1.0)

**FR-NOTIF-001: Email-уведомления**
- Асинхронная отправка через Bull Queue
- Шаблоны: новое бронирование, напоминание, отмена, перенос
- Настраиваемый SMTP (поддержка Gmail, корпоративных серверов)

**FR-NOTIF-002: Telegram-уведомления**
- Telegram Bot для мгновенных уведомлений
- Привязка Telegram аккаунта к профилю
- Команды бота: `/start`, `/bookings`, `/help`
- Уведомления о бронированиях и напоминания

**FR-NOTIF-003: Настройки уведомлений**
- Каналы: EMAIL, PUSH, TELEGRAM, SMS
- Статусы: PENDING, SENT, FAILED
- Типы: NEW_BOOKING, REMINDER_1H, REMINDER_24H, CANCELLATION, RESCHEDULE, NEW_MESSAGE, NEW_REVIEW, ACHIEVEMENT_UNLOCKED, GOAL_COMPLETED, PAYMENT_RECEIVED
- Логирование всех отправленных уведомлений

**Acceptance Criteria:**
- [ ] Email доставляется в течение 30 секунд
- [ ] Telegram-уведомление доставляется мгновенно
- [ ] При сбое доставки статус меняется на FAILED
- [ ] Пользователь может отключить каналы уведомлений

### 5.7 Модуль отзывов и рейтингов (v2.0)

**FR-REV-001: Создание отзыва**
- Менти оставляет отзыв только после завершённой сессии (COMPLETED)
- 5 параметров оценки (1-5 звёзд):
  - Общий рейтинг (overall)
  - Знания и экспертиза (knowledge)
  - Коммуникация (communication)
  - Полезность (helpfulness)
  - Ценность за деньги (value)
- Текстовый комментарий (опционально)
- Заголовок отзыва (опционально)

**FR-REV-002: Управление отзывами**
- Редактирование в течение 7 дней после создания
- Удаление отзыва автором
- Ответ ментора на отзыв (mentorResponse)
- Пометка «Полезно» другими пользователями (helpfulCount)

**FR-REV-003: Статистика рейтингов**
- Средний рейтинг ментора (по каждому параметру)
- Распределение оценок (1-5)
- Общее количество отзывов
- Тренды рейтинга со временем

**Acceptance Criteria:**
- [ ] Отзыв можно оставить только к завершённому бронированию
- [ ] Один менти — один отзыв на одно бронирование
- [ ] Средний рейтинг автоматически пересчитывается
- [ ] Ментор может ответить на каждый отзыв
- [ ] Отзыв нельзя редактировать после 7 дней

### 5.8 Модуль платежей (v2.0)

**FR-PAY-001: Приём платежей**
- Интеграция со Stripe для процессинга
- Поддержка 135+ валют
- Создание Payment Intent при бронировании
- Обработка Stripe Webhooks (payment_intent.succeeded, charge.refunded, и др.)

**FR-PAY-002: Выплаты менторам**
- Stripe Connect для выплат на счёт ментора
- Модель распределения: 90% ментору / 10% платформе
- Автоматический расчёт при успешном платеже
- История выплат и статистика заработка

**FR-PAY-003: Подписки**
- Рекуррентные подписки через Stripe Subscriptions
- Статусы: ACTIVE, CANCELLED, PAST_DUE, EXPIRED
- Привязка к Stripe Customer ID и Subscription ID

**FR-PAY-004: Возвраты**
- Управление возвратами через Stripe
- Автоматическая обработка по webhook
- Статусы платежа: PENDING, COMPLETED, FAILED, REFUNDED

**Acceptance Criteria:**
- [ ] Платёж обрабатывается до подтверждения бронирования
- [ ] При отмене в соответствии с политикой — автоматический возврат
- [ ] Ментор видит заработок в личном кабинете
- [ ] Комиссия платформы 10% корректно рассчитывается
- [ ] Все платёжные события логируются

---

### 5.9 Модуль обмена сообщениями (v2.0)

**FR-MSG-001: Реал-тайм мессенджер**
- WebSocket (Socket.io) для мгновенной доставки
- 1-на-1 беседы между ментором и менти
- Типы сообщений: TEXT, IMAGE, FILE, VOICE, VIDEO
- Индикаторы набора текста (typing)
- Отметки о прочтении (read receipts)

**FR-MSG-002: Управление беседами**
- Создание беседы при первом контакте
- Список бесед с last message и unread count
- Пагинация истории сообщений
- Присоединение к комнате беседы (joinConversation)

**FR-MSG-003: Уведомления о сообщениях**
- Push-уведомление при новом сообщении
- Счётчик непрочитанных
- Уведомление типа NEW_MESSAGE через модуль уведомлений

**Acceptance Criteria:**
- [ ] Сообщение доставляется в реальном времени (< 500ms)
- [ ] Оффлайн-пользователь получает уведомление о пропущенном сообщении
- [ ] Счётчик непрочитанных корректно обновляется
- [ ] Файлы и изображения корректно прикрепляются

### 6.2 Масштабируемость

- Горизонтальное масштабирование API через контейнеризацию
- PostgreSQL с connection pooling (Prisma)
- Redis для кэширования и очередей
- Stateless JWT-аутентификация (масштабируется без сессий)

### 6.3 Безопасность

| Требование | Реализация |
|-----------|-----------|
| Аутентификация | JWT + bcrypt (10+ rounds) |
| Авторизация | RBAC (MENTOR, MENTEE, ADMIN) |
| Валидация ввода | class-validator + whitelist |
| CORS | Настраиваемый список разрешённых origins |
| Инъекции | Prisma ORM (параметризованные запросы) |
| XSS | Валидация и экранирование на frontend |
| Rate limiting | Настроен в конфигурации (RATE_LIMIT_TTL, RATE_LIMIT_MAX) |
| Секреты | Переменные окружения (.env), не в коде |

### 6.4 Надёжность

- Uptime target: 99.5%
- Graceful degradation при недоступности внешних сервисов (Stripe, Telegram)
- Асинхронная обработка тяжёлых операций через Bull Queue
- Логирование ошибок и аудит действий (AuditLog модель)

### 6.5 Доступность (Accessibility)

- WCAG 2.1 AA compliance (целевой уровень)
- Mobile-first responsive design
- Поддержка screen readers
- Клавиатурная навигация

### 6.6 Локализация и интернационализация

- Мультиязычный интерфейс (стартовые: EN, RU)
- Timezone-aware расписание и уведомления
- Мультивалютные платежи (135+ валют через Stripe)
- Локализация форматов дат и чисел

## 10. Пользовательские сценарии (User Flows)

### 10.1 Менти: Поиск и бронирование ментора

```
1. Менти заходит на маркетплейс (/marketplace)
2. Использует фильтры: категория, цена, рейтинг, язык
3. Просматривает профили менторов с отзывами
4. Выбирает ментора → переходит в профиль
5. Выбирает тип встречи (напр. "Разбор кода", 60 мин, $80)
6. Видит доступные слоты в своём часовом поясе
7. Выбирает дату и время
8. Заполняет форму бронирования (описание запроса)
9. Оплачивает через Stripe
10. Получает подтверждение (Email + Telegram)
11. За 24ч и 1ч получает напоминания
12. Проводит сессию
13. Бронирование переводится в COMPLETED
14. Оставляет отзыв (5 параметров + комментарий)
15. Получает 50 очков за сессию + 20 за отзыв
```

### 10.2 Ментор: Настройка и ведение практики

```
1. Ментор регистрируется с ролью MENTOR
2. Заполняет профиль: био, экспертиза, ставка, фото
3. Выбирает категории экспертизы
4. Создаёт типы встреч (напр. "Карьерная консультация", "Code Review")
5. Настраивает еженедельное расписание доступности
6. Делает профиль публичным (isPublic: true)
7. Получает уведомление о новом бронировании
8. Подтверждает бронирование (PENDING → CONFIRMED)
9. Проводит сессию
10. Получает оплату (90% от суммы) на Stripe Connect
11. Читает отзыв менти, отвечает при необходимости
12. Отслеживает статистику: рейтинг, кол-во сессий, заработок
13. Поднимается в лидерборде
```

### 10.3 Менти: Отслеживание прогресса

```
1. Менти создаёт цель: "Освоить системный дизайн за 3 месяца"
2. Добавляет вехи:
   - Прочитать "Designing Data-Intensive Applications"
   - Решить 10 задач по System Design
   - Пройти 5 mock-интервью с ментором
3. Отмечает вехи по мере прохождения
4. Прогресс автоматически обновляется (0% → 33% → 66% → 100%)
5. При 100% — статус COMPLETED, +100 очков
6. Разблокируется достижение "Goal Crusher"
```

### 10.4 Менти + Ментор: Обмен сообщениями

```
1. Менти отправляет сообщение ментору (создаётся беседа)
2. Ментор получает уведомление (Email / Telegram / Push)
3. Ментор открывает чат и отвечает в реальном времени
4. Сообщения доставляются через WebSocket мгновенно
5. Оффлайн-пользователь видит счётчик непрочитанных
6. Обмен файлами, изображениями и голосовыми сообщениями
```

### 10.5 Администратор: Модерация платформы

```
1. Администратор заходит в /admin/dashboard
2. Видит общую статистику: пользователи, бронирования, выручка
3. Переходит в управление пользователями
4. Фильтрует по роли, статусу
5. При необходимости деактивирует аккаунт
6. Просматривает все бронирования, разрешает споры
7. Управляет featured-менторами в маркетплейсе
```

## 14. Риски и ограничения

### 14.1 Технические риски

| Риск | Вероятность | Влияние | Митигация |
|------|------------|---------|-----------|

| N+1 запросы при масштабировании | Высокая | Среднее | Code review, query optimization |

### 14.2 Бизнес-риски

| Риск | Вероятность | Влияние | Митигация |
|------|------------|---------|-----------|

| Ценовая конкуренция | Средняя | Среднее | Дифференциация через геймификацию и аналитику |
| Регуляторные ограничения (разные юрисдикции) | Средняя | Высокое | Юридический аудит для ключевых рынков |

2. **Нет мобильных приложений** — только веб-версия
3. **Нет видеоконференций** — сессии проводятся через внешние инструменты
